# 双列动态卡片内容自适应高度与死白消除

> 创建：2026-10-06 · 状态：已修复

## 现象

1. **短文本卡片存在大面积空洞死白**：在首页双列卡片（Feed）视图中，当用户记录仅有几个字（如“明天的晚饭”、“测试动态”）时，卡片内部从文字到底部作者时间栏之间被撑出了近 80px~90px 的无内容空白（死白），屏效极低；
2. **长短动态高度机械一致**：1 行极短字数的卡片与 4~5 行的多文字语音动态卡片被强行撑到了完全相同的高度（约 150px~160px），双列瀑布流退化为类似呆板方格的固定高度矩阵，丧失了瀑布流自然咬合的错落美感。

## 期望行为

1. **下限自然收缩，消灭死白**：无封面纯文字卡片的高度完全由内容物理撑开，短动态（1 行）紧凑收缩至便签尺寸（~76px），作者与时间栏紧随其后，符合格式塔亲密性法则；
2. **上限严格封顶，杜绝失衡**：保留 `line-clamp-4`（标题 `line-clamp-2`），多字动态在达到上限后自动截断，严控最大高度在 ~135px 左右，杜绝“竹竿效应”破坏两列平衡；
3. **首位速记卡适度收敛**：首格速记卡高度与左右流协同，避免过度夸张的纵向撑开；
4. **无标题便签主次分明**：无独立标题的短动态文字以 `text-primary` 清晰呈现，保留出版物微便笺质感。

## 根因与修复（第一性原理）

1. **下限硬编码与强制推底违背瀑布流物理盒模型**：
   - **根因**：`MomentCard.tsx` 在无封面卡片内容区强制设定了 `min-h-[130px]`，并叠加 `justify-between` 与底部栏 `mt-auto`。该模式照搬了小红书强封面卡片的上下对齐，忽视了亲密空间中大量无图日常碎碎念的场景本质，将下限硬编码在了上限（4 行文字约 130px）的位置，迫使 1 行字拉伸出 60% 死白。
   - **修复**：
     - 彻底移除 `min-h-[130px]` 与 `mt-auto`，移除外层无意义的 `justify-between`；
     - 让卡片盒模型回归纯粹的 Flex 垂直流：内容（语音指示/标题/正文）自适应撑开，底部元数据（作者与时间）通过设计系统规范的微内边距与分割线（`pt-2 border-t`）自然衔接；
     - 无独立标题时，正文由次要灰字升级为 `text-primary` 主文字，强化短动态的便签重心。
2. **首位速记入口卡容器尺度协调**：
   - **根因**：`MomentComposeCard.tsx` 在双列模式下硬编码 `min-h-[130px] sm:min-h-[150px]`，导致首行左右落差突兀。
   - **修复**：收敛最小高度至 `min-h-[105px] sm:min-h-[115px]`，既维持速记卡上中下三层结构的呼吸感，又与自适应卡片保持更优雅的同屏比例。
