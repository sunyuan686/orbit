# Bug #5：移动端/PWA 下日期选择弹出软键盘且弹窗右侧被视口裁剪

| 字段 | 内容 |
|------|------|
| 状态 | 🟢 已修复 |
| 发现日期 | 2026-08-19 |
| 修复日期 | 2026-08-19 |
| 影响范围 | 移动端/PWA 视图下的所有日期选择场景（如 `ArticleEdit` 文章编辑元数据栏、`SpaceSettingsPanel` 空间设置等） |
| 相关文件 | `web/src/components/DatePicker.tsx`、`web/src/index.css` |

## 现象

1. **软键盘弹出挤占屏幕**：在 iPhone/Android 移动端或 PWA 模式下，点击文章编辑页正文头部的日期（如 `2026-08-19`），系统自动弹出了全尺寸虚拟软键盘，遮挡近一半屏幕高度与日历面板。
2. **面板右侧被裁剪**：日历浮层与右边框紧贴，最右侧的「日（星期日）」列及边框阴影被裁切到屏幕外，用户无法正常点选周日日期。

## 根因分析

1. **软键盘根因**：`DatePicker` 组件内部使用原生 `<input type="text" />`，点击触发器时调用了 `inputRef.current?.focus()`。移动端浏览器/PWA 检测到可编辑文本输入框聚焦，强制调起系统软键盘。
2. **右侧裁剪根因**：
   - 浮层使用 `position: absolute; left: 0; width: 22rem (352px)`；
   - 在文章编辑页中，`DatePicker` 位于正文头部元信息栏（`作者：xxx • [📅 2026-08-19]`），距离屏幕左侧约有 110px 偏移量；
   - 浮层右侧边界达到 `110px + 352px = 462px`，远超过手机常规屏幕宽度（375px~393px），导致右侧发生视口溢出（Viewport Overflow）被截断。

## 修复方案

从第一性原理与移动端最佳实践出发，重构交互与响应式表现：

1. **触屏/移动端防调键盘**：
   - 在触摸或小屏环境下（`pointer: coarse` / `max-width: 640px`），将 `<input>` 属性设为 `readOnly` 与 `inputMode="none"`；
   - 点击时切换面板状态，不触发文本输入聚焦，彻底避免软键盘唤起；
   - 桌面端（鼠标环境）继续保留原生键盘直接输入与回车解析能力。
2. **移动端响应式升级为底部抽屉（Bottom Sheet）**：
   - 移动端（`max-width: 640px`）通过固定定位 `position: fixed` 将浮层转为底部抽屉卡片，配合半透明背景遮罩（Backdrop）与手势提手（Handle）；
   - 底部适配 iPhone 底部安全区（`env(safe-area-inset-bottom)`）；
   - 桌面端（>640px）保持精巧的下挂气泡卡片。
3. **滚动锁定**：移动端抽屉唤起时自动锁定页面背景滚动，防止手势穿透。
