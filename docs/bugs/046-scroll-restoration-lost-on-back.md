# 详情页返回列表后主内容区滚动位置重置为顶部

> 创建：2026-09-24 ·
> 状态：已修复

## 现象

用户在动态流（或其他列表页）向下滑动浏览到某个位置，点击卡片进入详情页查看，随后通过顶栏返回按钮（或移动端边缘侧滑返回手势）回到列表页时，页面未停留在当时浏览的偏置位置，而是被重置滚回到了最顶部（0），让用户产生“页面被刷新了”的体验割裂感。

## 期望行为

- 从详情页返回列表页时，页面应准确停留在进入详情前的滚动浏览位置；
- 打开标签管理、搜索、创作抽屉等呈现层（`useLayer`）浮层时，底层主内容区滚动位置保持不动，不触发归零；
- 全新导航（PUSH / 跨页 REPLACE）进新页面时，页面从顶部（0）开始展示；
- 列表异步数据或图片占位在首帧尚未完全展开时，系统应具备自适应对齐能力，且在用户主动触摸屏幕时立即将视口控制权移交用户手势。

## 根因与修复（零补丁·第一性原理）

### 根因分析

1. **DOM 节点替换瞬时高度骤降触发原生截断（Clamp）覆写 0（核心根因）**：
   - 当用户在长页面（如恋爱记忆星图、动态长列表）滚动至较大偏置（如 1200px+）并点击卡片进入详情时，React 提交新路由并将前一页 DOM 卸载，挂载新页面；
   - 新页面在初始挂载时通常处于异步加载（如渲染简短骨架屏或 `<p>加载中…</p>`），容器 `scrollHeight` 瞬间骤降至数百像素甚至小于容器视口高度；
   - 浏览器原生引擎在容器内容收缩时会**强制同步将 `scrollTop` 截断（clamp）为 `0`**；
   - 若依赖离场时刻的 `scrollTop` 或无门禁的滚动监听，该原生截断产生的归零值会被立刻记录，将记忆星图原本的 1200px 覆盖为 0；
   - 用户返回时读取到的目标偏置已被污染为 0。

2. **POP 恢复时 DOM 节点仍在异步组装，单帧恢复失效**：
   - 记忆星图包含天幕伪随机星空、回忆档案流、里程碑卡片与热力图。从详情返回重新挂载时，尽管 React Query 有缓存，组件的多层级渲染与图片排版仍需数个渲染帧；
   - 仅靠单一帧检测若容器高度尚未撑开便直接放弃，会导致恢复动作夭折。

3. **呈现层（`useLayer`）操作与页面级导航未区分**：
   - 弹窗和抽屉由 `useLayer` 压入同 URL 历史条目（同为 PUSH），旧逻辑无脑在 PUSH 时重置 `el.scrollTop = 0`，导致打开浮层时底页也被连带滚回顶部。

### 零补丁第一性原理修复

1. **容器物理几何法则（Physical Overflow Existence）**：
   - 监听原生 `scroll` 事件，严格依据容器物理几何特征判定：
   - 只有当 `el.scrollHeight > el.clientHeight`（容器真实具备可滚动物理溢出空间）时才处理；
   - 一旦 `el.scrollHeight <= el.clientHeight`，说明子视图已卸载或内容已坍塌，此时产生的 `scrollTop = 0` 100% 属于浏览器底层被动 Clamping 截断，物理级切断记录，零补丁、零状态标志位依赖；
2. **物理运动连续性法则（Continuous Motion Law）**：
   - 人类滑动必然遵循时间空间连续性采样，绝不可能在单事件帧内无中间位移从 >80px 瞬移至 0px；
   - 若前一次记录偏置 > 80px 且单帧突降为 0px，100% 属于 DOM 节点替换或程序赋值引发的假性归零，切断覆写；
3. **触控生命周期与侧滑返回保护**：
   - 彻底废弃易受单击卡片污染的 `isUserInteracting` / `touchstart` 常开标志位；
   - 恢复自适应对齐器的熔断器仅监听真实产生滚动物理位移的 `wheel` 与 `touchmove`，严禁在 `touchstart`/`pointerdown` 上无脑熔断，彻底保护 iOS 屏幕左边缘侧滑返回手势；
4. **多阶自适应异步对齐（12 帧 RAF + ResizeObserver + MutationObserver）**：
   - 返回页面（POP）时首帧恢复目标偏置，配合短周期紧密 RAF 轮询覆盖 React 批处理，并用双 Observer 实时监听星图天幕与卡片异步渲染撑开高度，精准到位即刻注销；
5. **会话级持久化（`sessionStorage`）**：
   - `scrollPositions.ts` 在内存 Map 基础上无缝同步 `sessionStorage`，并挂载 `pagehide` / `beforeunload` 原子存照，确保跨刷新与 PWA 会话不丢偏置。
6. **Tab 视口与次级视口架构对齐（`TabKeepAliveHost`）**：
   - **主 Tab 视口（动态、相册、信箱、我们）**：剔除 `contentVisibility: hidden`，保留纯 `visibility: hidden`。由浏览器底层 100% 原生持久化盒模型与滚动偏置；
   - **次级视口（记忆星图、相册详情、文章详情、设置等）**：在 `orbit-subpage-viewport` 接入该第一性原理恢复机制，实现二级栈式路由离开防踏空、返回首帧同步恢复与异步多维自适应对齐。
