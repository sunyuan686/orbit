| 修复日期 | 2026-09-03 |

## 现象与本质原因

### 1. 现象描述
在移动端（尤其是 iOS Standalone PWA 或触屏设备）下打开 AI 对话面板时：
- 当点击输入框唤起虚拟键盘时，在半透明毛玻璃键盘背后、或者键盘弹出/收起动效间隙以及拖拽边缘，能够透过键盘清晰看到底层的“首页”（包括首页的 Feed 流、Bento 卡片或文章等内容）；
- 用户从心智上感觉 AI 会话层“漏底”、缺乏原生应用的实体隔离感。

### 2. 根因分析（第一性原理剖析）
1. **面板外壳高度被硬性截断，底部悬空留白**：
   - 先前为了使输入栏贴在键盘上方，代码在键盘唤起时通过 `window.visualViewport.height` 强行将 `.orbit-ai-panel` 的高度压缩为 `var(--ai-vv-height)`（例如 504px）；
   - 这导致 `.orbit-ai-panel` 的实体 DOM **只覆盖了屏幕上半部分**；在键盘所在的下半截屏幕（504px 至物理底部 844px），面板本身完全不存在，直接悬空。
2. **底层遮罩是半透明的，无遮蔽能力**：
   - 在面板悬空后，键盘后方的唯一屏障是 `.orbit-ai-overlay::before`。但在全局样式中，遮罩使用的是半透明 Token（`--color-overlay`，暗黑模式下为 50% 半透明黑，浅色为 35%）；
   - 该遮罩本身严重透光，正后方直接是应用首页的内容。
3. **输入法毛玻璃采样与渲染时差放大问题**：
   - iOS 系统原生键盘、微信输入法等第三方键盘普遍采用实时背景模糊（Blur Effect）；因为键盘底下只有 50% 半透明遮罩和首页，毛玻璃直接将首页的彩色内容模糊透视出来；
   - 键盘动画和 WebKit resize 事件的帧差使下沿缝隙暴露出底层首页。

---

## 解决方案（基于第一性原理，拒绝胶水补丁）

1. **移动端 AI 遮罩实体化（第一道物理防线）**：
   - 移动端下 AI 对话是独占全屏页面而非桌面侧边栏。在 `@media (max-width: 767px)` 下，将激活的 `.orbit-ai-overlay--visible::before` 重构为 100% 不透明实心背景色（`background: var(--color-bg) !important; opacity: 1 !important;`），从根本上物理切断底层页面的任何透光可能。
2. **面板外壳顶天立地，全屏满高实体覆盖（第二道物理防线）**：
   - `.orbit-ai-panel` 始终保持 `top: 0; left: 0; right: 0; bottom: 0; width: 100%; height: 100%; max-height: 100%;`，拥有实体 `background: var(--color-bg)`；
   - 外壳绝对不缩短截断，从屏幕顶部物理铺满到屏幕最底部（包括键盘下方全域）。
3. **键盘避让由内部 Padding 驱动（心智与布局正确解耦）**：
   - 键盘高度通过 `--ai-keyboard-height` 计算（`window.innerHeight - vv.height`），直接作用于 `.orbit-ai-panel` 的 `padding-bottom`；
   - 输入框自然随 flex 布局顶到键盘上方，消息列表在可视区内自适应滚动；键盘背后的留白区属于面板自身的实心背景，彻底消除漏底。

---

## 验证标准

- `npm run web:build` 与 `npm run typecheck` 编译通过（0 error）；
- 移动端唤起输入法键盘时，键盘背后完全是 AI 面板的实心底色，绝不透出首页任何像素；
- 键盘弹起与收起时，输入栏贴合平滑，无缝隙闪烁与跳白；
- 桌面端侧边栏、浮动面板模式保持原有半透明遮罩与多窗口特性不变。
