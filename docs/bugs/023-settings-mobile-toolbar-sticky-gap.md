## 现象与本质原因

### 1. 现象描述
在移动端（手机 / iOS PWA）进入设置的二级详情分类（如“主题与外观”、“个人资料”等）后向下滑动浏览时：
- 顶部的全局导航栏（`.orbit-header-bar`，包含 Orbit 标题及搜索/通知等）与悬浮的二级返回栏（`< 设置`，`.orbit-settings-mobile-toolbar`）之间存在一段约 48px 的透明空隙；
- 页面下方的卡片（如“草木深绿”等设置项）在向上滚动时，会从 `< 设置` 返回栏下方滑过，并穿透重新在上方这 48px 的空隙中裸露现身；
- 造成内容被横向截断、上下夹心穿透的严重排版割裂感。

### 2. 根因分析（第一性原理剖析）
1. **反模式的双层吸顶叠加（Double-Header Gap Anti-pattern）**：
   - 页面最顶部已经固定常驻了全局系统栏 `.orbit-header-bar`；
   - 在二级内容中，又给容器内的 `.orbit-settings-mobile-toolbar` 声明了 `position: sticky; top: 0;`；
2. **容器内外边距导致吸顶位置与视觉割裂**：
   - 滚动容器 `<main>` 声明了 `py-6`（顶部内边距 24px），内层 `<Container>` 声明了 `padding-top: 1.5rem`（顶部内边距 24px）；
   - 在 CSS 规范中，Sticky 元素的活动空间严格受限于其直接父级容器 `<Container>` 的内容框，无法脱离容器边框贴到窗口真正最顶部；
   - 结果该吸顶栏被固定在距离顶部 48px 的半空，而下方滚动的卡片沿着滚动容器向上移动时，直接穿越吸顶栏背后并从上方未遮盖的 48px 内边距空间露了出来。

---

## 解决方案（基于业界最佳实践，拒绝胶水补丁）

1. **遵循留白克制美学，回归标准文档流**：
   - 遵循 [DESIGN.md](DESIGN.md) 与整站刊物文学排版哲学（参考文章详情页 `ArticleView` 的 `< 返回列表` 标准）；
   - 移动端二级返回栏无需作为第二层吸顶栏常驻（小屏手机上双层常驻 Header 会吃掉近 100px 纵向高度），而是作为页面顶部纯净的导航回退入口；
   - 移除 `.orbit-settings-mobile-toolbar` 上冗余的 `position: sticky; top: 0; z-index: 2; background: var(--color-bg);`；
   - 页面滚动时，所有内容统一平滑向上滑入顶部菜单下方消失，从根本上物理消除“夹心中空、内容穿透”的断层 Bug。

## 验证标准

- `npm run web:build` 与 `npm run typecheck` 编译通过（0 error）；
- 移动端进入各设置分类（如主题与外观、个人资料、安全等），滚动页面时，内容与返回按钮整体自然平滑滚动；
- 顶部导航栏与内容之间过渡自然，彻底消除穿透、重影与断层空隙。
