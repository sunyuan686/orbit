# 录音卡片提取纯文本泄漏播放器控件与字符污染

> 创建：2026-09-09 · 
> 状态：已解决

## 问题现象

动态流中包含语音录音的卡片，其正文摘要（`snippet`）显示混乱：
- 摘要开头硬塞了 `🎙️ [语音]`；
- 播放器的界面文字（如播放进度时长 `0:00`、展开按钮文字 `💬文稿`）被当成正文全部漏了出来；
- 讲话转写文稿在摘要中被重复读取了两遍。

## 根本原因分析

1. **嵌套标签匹配缺陷**：富文本 HTML 中的音频块为多层嵌套 `div`（包含外层卡片容器、波形行、播放按钮行等子 `div`）。原 `src/lib/plain-text.ts` 仅使用 `indexOf("</div>")` 寻找结束，错误匹配到第一个子行的闭合，导致后续所有控件 DOM 节点被逃逸当成常规正文解析。
2. **前后端胶水字符耦合**：原逻辑在 `toPlainText` 中手动拼接了 `🎙️ [语音]` 字符串供前端卡片识别媒体类型，混淆了正文与元数据职责。

## 解决方案

1. 在 `src/lib/plain-text.ts` 中引入纯字符单趟扫描深度状态机（`depth`），完整跳过音频卡片所有子控件，仅提取纯净文稿并移除 `🎙️ [语音]`。
2. 在 API 层增加结构化 `hasAudio: boolean` 字段，替代前端字符串嗅探。
3. 运行 `scripts/backfill-body-text.ts` 清洗已有历史存量数据。
