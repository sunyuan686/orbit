# 移动端/PWA 首页滑动时刮刮卡误刮与滚动被拦截

> 创建：2026-08-30 · 
> 状态：已修复

## 现象

在移动端（尤其是 iOS / Android PWA 或移动 Safari）访问首页时，用户在屏幕中间（时光刮刮乐卡片区域）通过手指上下滑动浏览页面（如查看下方的「最近照片」）时，出现以下问题：
1. **页面无法正常滚动**：手指在刮刮卡区域上下滑动时，页面滚动被完全拦截；
2. **产生误刮痕迹**：手指刚接触卡片或滑动时，涂层立即被擦除留下大片刮痕；
3. **误触发永久揭晓**：误触滑动擦除面积达到 30% 时，卡片被自动揭晓并向 `localStorage` 写入当日已揭晓状态，导致回忆卡被非预期提前翻开。

## 期望行为

1. **纵向滑动丝滑浏览**：用户在刮刮卡区域上下滑动时，页面正常流畅垂直滚动，卡片涂层保持完好，不产生任何误刮；
2. **意图识别与自然刮卡**：当用户横向擦拭、来回摩擦或使用鼠标拖拽时，精准判定为刮卡意图，平滑擦除涂层；
3. **手势生命周期完整**：支持 `pointercancel` 与手势释放，滑走或离开时不残留异常捕获状态。

## 根因与修复

1. **根因**：
   - **CSS 拦截原生手势**：`.orbit-scratch-container` 设置了 `touch-action: none`，通知浏览器禁止此区域的所有原生平移与滚动手势。
   - **按下即破坏涂层**：`onPointerDown` 瞬间直接调用 `scratch()` 擦除 22px 半径圆形，无任何 Touch Slop（手势死区）与意图仲裁。
   - **高频全量擦除**：`onPointerMove` 未做方向判定与连线插值，且高频调用同步 `getImageData` 进行像素检测。

2. **修复措施（方案 A · 沉浸式弹层刮卡 · Google Pay 级标准实践）**：
   - **空间物理隔离 (Physical Space Disambiguation)**：
     - **首页 Feed 常态**：未揭晓时呈现精美特种纸票券封皮（`orbit-scratch-feed-cover`），属于纯静态 DOM，完全透传浏览器原生异步滚动；手指滑过卡片浏览 Feed 时 100% 丝滑顺畅，**绝对 0 误触、0 误刮**；
     - **沉浸式刮卡弹窗 (`ScratchModal`)**：用户轻点卡片后，优雅弹入全屏高斯模糊遮罩（`backdrop-filter: blur(14px)`）与独立刮卡视窗，并锁死底层页面滚动；
     - **畅快自由涂抹**：在独立视窗中没有任何滚动竞争，声明 `touch-action: none`，用户可 360° 任意用力涂抹、斜划、画圈狂刮；
   - **平滑连线擦除与 Web Audio 物理音效**：
     - 使用带通白噪合成器（1800Hz~3000Hz）随手指刮动速度实时调节音量与频率，并在抬手瞬间静音；
     - 擦除面积达到 28% 时自动播放揭晓动效，同步写入 `localStorage` 并沉淀回首页展示。
