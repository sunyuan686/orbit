# 信箱选中时间后年份下拉选项缩水

> 创建：2026-10-06 ·
> 状态：已修复

## 现象

信箱页面在时间筛选器中选中某一年份（如“2025年”）后，再次展开时间下拉框，历史年份选项（如 2022~2025 年）消失，仅剩下“全部”和“2026年”。

## 期望行为

时间筛选器的下拉选项应反映信箱历史全量内容的年份跨度（如 2022 ~ 2026 年），无论当前选中了哪一年、或当前年份是否有信件，时间下拉选项应保持稳定完整，方便用户自由切换不同年份。

## 根因与修复

### 根因
信箱（`letter`）是非分页的全量视图，后端未在响应中单独返回 `earliestYear` 元数据。前端 `ArticleList.tsx` 错误地直接遍历当前查询结果 `entries` 计算最早年份 `earliestYear`。当用户选中某一年后，后端返回的数据仅包含该年份信件（若该年无信件则返回空数组），导致 `earliestYear` 退化为当前系统年份（2026），使得比 2026 更早的年份从下拉选项中全部丢失。

### 修复
根据信箱“全量拉取以拼信件树”的不变量设计：
1. 信箱 Query 固定拉取全量信件，解耦元数据与局部筛选；
2. 全局最早年份 `earliestYear` 与作者选项基于全量信件数据稳定派生，不受局部筛选参数影响；
3. 年份与作者筛选在客户端即时过滤，既保持年份下拉选项的全局完整性，又实现切换筛选 0 延迟响应。

## 回归验证

- 选中 2025 年（无信件）后，展开时间选择器，依然完整包含 2022 ~ 2026 年所有选项。
- 可在 2025、2024、全部之间自由切换，信件列表正确筛选。
- `npm run web:build` 类型检查与构建通过。
