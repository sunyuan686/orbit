# Bug #14：移动端/PWA 展开菜单时 Brand 头部 Sticky Hover 假选中与信息冗余治理

| 字段 | 内容 |

| 修复日期 | 2026-09-03 |
| 影响范围 | 移动端/PWA 导航抽屉、侧边栏品牌头部、导航列表项、账号菜单 |

## 现象与本质原因

### 1. 现象描述
1. 在移动端 / PWA 下，用户点击左上角汉堡按钮打开侧边抽屉菜单时，抽屉顶部的 **「Orbit 在一起第 XXX 天」** 会立刻被一个浅灰色圆角卡片包裹，视觉上呈现为“被选中 / 激活”的状态，与下方的「首页」导航项选中态极其混淆。
2. 菜单栏顶部堆砌了「在一起第 XXX 天」，与首页核心看板（Hero）展示重叠，且在侧边栏狭窄空间内造成信息噪音。

### 2. 根因分析
1. **触控坐标重叠与模拟事件派发**：
   - 移动端汉堡菜单按钮位于左上角。点击展开抽屉时，抽屉顶部的品牌链接刚好出现在手指点击的屏幕坐标区域。
   - 移动端 WebKit 在 `touchend` 后派发模拟的鼠标事件（`mouseenter` / `mouseover`），使品牌链接触发了 `:hover` 伪类。
2. **移动端 Sticky Hover（悬停粘滞）机制**：
   - 触屏设备无鼠标移出操作，`:hover` 会一直粘滞保持，直到用户在其他地方再次触发点击。
3. **CSS 缺少 Pointer 介质限制**：
   - `.orbit-sidebar-brand-link:hover` 未包裹在 `@media (hover: hover) and (pointer: fine)` 内，直接声明了 `background: var(--sidebar-nav-hover-bg)`。
4. **信息架构冗余**：
   - 空间档案天数已在首页作为核心情感看板呈现，无需在侧边栏重复常驻。

---

## 解决方案（业界最佳实践）

1. **侧边栏 Header 极简纯粹化**：
   - 移除侧边栏菜单顶部的「在一起第 N 天」副标题，仅保留纯净优雅的「Orbit」空间名称，消除信息噪音与冗余。
2. **输入介质严格隔离 (`@media (hover: hover) and (pointer: fine)`)**：
   - 将侧边栏品牌链接、导航项（`.orbit-nav-item`）、账号触发器（`.orbit-sidebar-account-trigger`）及菜单项（`.orbit-sidebar-account-menu-item`）的 `:hover` 样式全部收敛至物理鼠标指针媒体查询中，彻底杜绝移动端触屏粘滞悬停。
3. **触控按压标准化 (`:active`)**：
   - 触控端采用标准的 `:active` 瞬时按压反馈，手指抬起或滑动时立即复原。
4. **抽屉无障碍与键盘交互增强**：
   - 侧边栏抽屉增加 `aria-label="主导航"`，并在抽屉打开时支持全局 `Escape` 快捷键关闭。

---

## 验证闭环

- `pnpm run web:build` 与 `pnpm run typecheck` 编译 0 错误；
- 移动端视口下点击汉堡按钮展开抽屉，顶部品牌区域保持安宁干净的「Orbit」纯文本标题展示，彻底消除了灰色假选中背景；
- 移动端点击导航项时具备瞬时 `:active` 反馈，离开后立即恢复；
- 桌面端物理光标悬停在 Brand Link 及导航项时，保持正确的浅灰色 hover 提示；
- 键盘 Tab 键导航时 `:focus-visible` 焦点环正常显示，按 `Escape` 键可正常关闭展开的抽屉。
