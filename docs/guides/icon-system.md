# Orbit 图标系统与设计哲学规范 (Icon System Guide)

本文档记录 Orbit 图标系统的架构设计、实现标准，以及基于**第一性原理**做出的关键技术与视觉决策（为何坚持静态单色、为何拒绝 Lottie 与过度动效），供后续开发与维护长期参考。

---

## 1. 第一性原理：图标的本质

1. **图标是「路标 (Signifier)」，而不是「演员」**
   - 用户使用搜索、返回、设置、删除等功能时，其核心需求是在 **0 毫秒内完成信息认知** 并达成操作意图。
   - 图标不应喧宾夺主。任何无实质意义的旋转、弹跳或变形（如汉堡菜单变叉号、垃圾桶掀盖），都会强行分散用户的视觉焦点，在长篇阅读与情感沉淀场景中演变为**视觉噪音**。

2. **服务于出版物文学温度与克制美**
   - 遵循 [DESIGN.md](../../DESIGN.md) 的 **60-30-10 黄金法则**：图标属于 **30% 墨水排版骨架** 的一部分。
   - 图标如同纸质书刊上的铅字，应当具备**沉静、稳定、内敛、克制**的质感，保持单色中性轮廓，告别彩色糖果盒与浮躁的微动效。

### 技术与样式铁律

| 维度 | 规范标准 | 说明与 rationale |
| :--- | :--- | :--- |
| **底层包装** | `<OrbitIcon>` | 统一包装组件，严禁业务组件私自复制或内联写死 `<svg>` |
| **视口基准** | `viewBox="0 0 24 24"` | 统一 24x24 网格系统 |
| **描边线宽** | `strokeWidth={1.5}` | 细腻克制，杜绝开源库常见的 2.0 粗描边 |
| **色彩策略** | `stroke="currentColor"` | 单色墨水风格，天然继承父级文字颜色与主题色切换 |
| **端点/拐角** | `round` / `round` | 柔和不生硬的微圆润过渡 |
| **标准尺寸阶梯** | `sm: 16px`<br>`nav: 16px`<br>`md: 20px` | 行内/操作一律 16px，导航一律 16px（消除与小字号排版的层级倒挂），极少强调场景使用 20px |
| **外部依赖** | **零 npm 图标库依赖** | 手写提取经典几何 Path（如 Feather/Lucide 底模）并深度自研 Orbit 专属星轨图标，构建产物仅几 KB |

## 3. 技术决策：为何拒绝引入 Lottie / 装饰性动效库

针对类似 `useAnimations` 等开源微动效库的调研与评估，Orbit 团队明确做出**不引入、不跟风**的架构决策：

1. **拒绝胶水代码 (No Glue Code)**
   - 为了实现图标的几何形变（Morphing），必须强行将原本纯粹规整的单个 `<path>` 拆解为多个带独立 class 的片段，并堆砌大量的 CSS `@keyframes`、时序贝塞尔曲线与状态还原代码。
   - 仅仅为了“好看”而破坏底层数据的直白与纯粹，是典型的过度抽象与胶水代码。
2. **拒绝运行时性能开销 (Cost Awareness)**
   - Lottie 动画引擎（`lottie-web`）引入通常带来 60KB ~ 150KB 的额外 JavaScript 运行时负载，且每个动画需要解析一段 JSON；
   - 对于主打秒开与低功耗的 PWA 应用，多处 Canvas/WebGL/DOM 动画实例会对移动端产生不必要的内存占用和电量消耗。
3. **拒绝破坏主题自适应**
   - 复杂的预制矢量动画往往硬编码颜色，难以原生融入 Orbit 基于 CSS 变量（`--text-primary`、`--accent`、暗色模式）的完整色彩阶梯。

## 4. 全站动效的唯一特例（物理必要性）

全站仅对**真正承载系统状态认知与物理输入感知**的场景保留极其克制的动态反馈，其余所有图标保持绝对静态：

1. **系统等待状态 (`LoadingIcon`)**
   - **场景**：异步网络通信、数据提交、删除确认中。
   - **表现**：单一线性匀速旋转（`animation: orbit-spin 0.6s linear infinite`）。
   - **目的**：告知用户“系统正在通信，并未卡死”。
2. **物理输入状态 (`VoiceInputButton`)**
   - **场景**：用户长按或点击开启麦克风录音中。
   - **表现**：红色微弱脉冲光圈（`animate-ping`）+ 实时音量均衡器高度起伏（`scaleY`）。
   - **目的**：提供硬件麦克风隐私安全警示，以及拾音强度的客观物理反馈。

## 5. 新增与维护规范

- **新增图标流程**：
  1. 确认该图标确实无法复用已有图元；
  2. 在 `OrbitIcons.tsx` 中使用 `<OrbitIcon>` 包装纯展示组件；
  3. 严格遵循 `strokeWidth={1.5}` 与 24x24 视口；
  4. 保持无状态纯函数形式，禁止混入业务逻辑。
