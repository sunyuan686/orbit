# 统一 private 与 public 的部署和发版文件

> 创建：2026-10-11 · 状态：已完成

## 目标

两仓库维护相同源码，实际部署参数和执行开关放到 GitHub Variables 或被忽略的本地配置。

## 步骤

1. 通用 Wrangler 模板生成本地部署配置，部署及远程数据库工具使用同一配置。
2. 部署、发版 workflow 分别由 `ENABLE_DEPLOY`、`ENABLE_RELEASE` 控制；沿用 private 作为唯一发版来源。
3. 自动清理 CHANGELOG 中依赖特定仓库历史的链接，统一 README 和本地同步技能。
4. 验证配置等价性、失败输入、工作流和构建；迁移现有参数到仓库变量。

## 完成标准（可验证）

- [x] 通用模板无实际部署标识，生成的私有配置保留原有资源和访问地址。
- [x] 测试、类型检查、构建、PWA 检查及 Worker 打包预检通过。
- [x] CHANGELOG 归一化可重复执行，版本内容保留。
- [x] 两仓库开关及部署参数配置完成，本地技能不再保留四处文件差异。

## 验证

- 67 项测试、根类型检查、前端构建、PWA 产物检查、Worker dry run 通过；workflow YAML 与 Shell 语法检查通过。
- 生成配置与原生产配置解析结果完全一致；已跟踪文件不再含原数据库 ID、站点地址和 VAPID 公钥。
- GitHub Variables 已回读核验：private 的部署及发版开关开启，public 两项关闭。
- 本地技能及实际配置均被 Git 忽略。实现验证阶段未操作远程数据库或部署；public 文件树待单独同步。
