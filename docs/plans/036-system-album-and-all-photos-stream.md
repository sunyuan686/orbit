# 相册首卡系统相册《生活留影》与全量照片流施工计划

> 创建：2026-09-06 · 
> 状态：已完成

## 目标

落实相册方案 B（首卡系统相册）：以系统保留相册《生活留影》（`id: "all"`）承载底层 `asset` 表的全量视觉资产。基于只读视图与动态投影实现，无需向数据库插入假数据 Migration，实现历史存量 311 张照片与未来动态发图无缝自动聚合，并修复自建相册图片上传时的 assetId 外键映射问题。

## 步骤

1. **后端服务层与 API 优化**：
   - 修改 `src/services/content/albums.ts`：
     - `listAlbums` 动态统计图片类 asset 总数及最新封面，构造并置顶系统相册《生活留影》（`id: "all"`）；
     - `getAlbum` 针对 `id: "all"` 直接查询全量图片资产并装配返回；
     - `updateAlbum` 和 `deleteAlbum` 增加对系统相册的保护拦截；
     - `addAssetsToAlbum` 兼容 `storageKey` 到 `asset.id` 的自愈映射。
   - 修改 `src/api/assets.ts`：
     - 上传接口返回数据中补充 `id: row.id`，保证前端获取标准资产标识。
2. **前端界面与交互适配**：
   - 修改 `web/src/pages/Albums.tsx`：
     - 为系统相册卡片增加精致的专属徽标或视觉识别；
     - 适配相册列表渲染与空状态。
   - 修改 `web/src/pages/AlbumDetail.tsx`：
     - 系统相册隐藏编辑、删除、设为封面等非适用操作；
     - 添加照片后自动刷新当前照片流；
     - 修复自建相册上传后添加照片时的参数传递。
3. **自动化验证与测试**：
   - 运行 `npm run typecheck` 与 `npm test`；
   - 运行构建验证 `npm run web:build`。
