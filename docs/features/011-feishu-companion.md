# 飞书主动陪伴与 AI 对话

> 在现有飞书 Bot（记事 / 指令查询 / 事件通知）之上，增加**主动陪伴推送**与**飞书内 AI 对话**。  
> 创建：2026-07-24
> 现状与基础接入见 [003-feishu.md](./003-feishu.md)。

状态：📋 规划中（未实现）

---

## 目标

1. **主动陪伴**：结合双方记录，在合适时机向飞书推送有温度的提醒/回顾，而不是只等人来问。
2. **出站统一为卡片**：主动推送与内容通知优先 interactive card，纯文本仅作兜底。
3. **飞书内可与 AI 聊天**：在 Bot 单聊（及可选群 @）里多轮对话，回答基于本空间内容，可回链网站。

非目标：替代网站编辑体验；把飞书做成通用客服 Bot。

---

## 与现状差距

| 现状 | 规划 |
| ---- | ---- |
| 内容通知默认关，且多为纯文本 | 偏好可开；统一卡片模板 |
| 仅里程碑等少数场景发卡片 | 陪伴推送、内容动态、摘要均卡片 |
| 无 Cron 陪伴节奏 | Cron + 事件触发 + 节流 |
| `/summary` 等单次指令，无多轮闲聊 | 会话态 AI 对话（与记事指令分流） |
| 站内 AI 面板与飞书断开 | 复用同一模型配置与内容检索能力 |

---

## 能力一：主动陪伴推送

### 触发

- **定时（Cron）**：如每日/每周固定窗口检查是否值得推送。
- **事件**：纪念日临近、连续未写、新里程碑、某条旧记录适合回味等。

### 素材与 AI

- 素材：近 N 天 diary / 留言 / 信 / 记忆节点等（只读摘要，控制 token）。
- AI 职责：判断「是否推」、生成短文案与卡片字段；**禁止编造未出现的事实**；可引用原文片段并附站内链接。
- 无可用模型时：降级为固定模板文案，或跳过该次推送。

### 节流与偏好

- 设置页按类型开关：内容动态 / 里程碑 / 陪伴提醒（可再拆子类型）。
- 每用户（或每空间）每日上限、同类去重、安静时段（如深夜不推）。
- 投递目标：沿用 Home Chat 或双方 open_id。

### 候选首批场景（待拍板 1～2 个落地）

- 今日未记轻提醒
- 随机/精选「翻旧账」一条
- 周回顾摘要
- 纪念日/周年临近提醒

---

## 能力二：飞书与 AI 聊天

### 交互

- 单聊默认可对话；群聊须 @Bot（与现有群门控一致）。
- 与记事指令分流：`/`、`搜`/`查`、以及明确写入前缀（如 `留言：`）仍走现有逻辑；其余自然语言进 AI 会话（或显式前缀如 `问：` / 模式开关，实现前再定）。
- 多轮：按 `chat_id`（+ 用户）保留短窗口上下文；超时或 `/clear` 清空。
- 回答可检索空间内容（FTS / 近期条目），并附可点开的 Orbit 链接。

### 约束

- 仅白名单 open_id；关闭飞书总开关则不响应。
- 复用站内已配置的 AI 供应商与模型；费用与超时需可观测、可降级。
- 不把机密设置（密钥等）注入模型上下文。

---

## 出站卡片约定

- 通用结构：标题、一两句正文、主按钮回站（详情 / 记忆页 / 今日等）。
- 内容通知、陪伴推送、里程碑尽量共用渲染层，避免每种消息一套拼装。
- 发送失败不阻断主流程；可记 audit / lastError 便于排查。

## 实现触及（预估）

- 出站：`sendFeishuInteractiveCard` 扩展为统一通知卡片构建
- 入站：`feishu-inbound` 增加 AI 对话分支与会话存储（D1）
- 设置：通知偏好扩展陪伴类开关；可选「飞书 AI 对话」总开关
- 复用：`ai-model`、搜索 / 条目摘要服务
