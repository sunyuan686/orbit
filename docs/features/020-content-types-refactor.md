# 内容类型收敛与信息架构重构

> 创建：2026-09-04 · 
> 状态：规划完成

## 背景与目标

目前系统定义了 7 类独立条目（日记、随想、感谢、时间线、留言板、信件、备忘录），造成了明显的“写作压力”与认知负荷：
1. **类型冗余与心智打架**：日常记录前需要做选择题，纠结到底发随想、日记、感谢还是留言；
2. **逻辑层次错配**：将属于枝叶属性的“感谢”和属于宏观章节的“时间线（足迹）”硬做成了平级内容类型；将工具属性的“备忘录”（仅 3 条数据）与承载深情回忆的动态、信件并排在主导航中；
3. **交互与展现形态割裂**：多模块套用同质化拍立得网格；移动端依赖桌面移植的汉堡抽屉，多级页面充斥着 PC 时代“面包屑”文字路径，输入门槛高；高频的相册缺乏独立的主题影集组织能力。

**终极目标**：
- 从第一性原理出发，确立 **“四大核心支柱（动态·相册·信箱·我们）+ 枝叶属性筛选”** 的极简架构；
- 在 Web 与移动端 **彻底废除面包屑导航**，打造原生轻量的移动底栏与零门槛即时发布体验；
- 采用现代工业界公认的 **“外壳解耦架构 (Clean Shell Architecture)”**，彻底拒绝“到处打 if/else 补丁”的代码恶臭，实现高内聚、低维护成本的工程治理；
- **视觉风格严格守恒**：重构聚焦于架构收敛与交互体验，全面遵循现行 `DESIGN.md` 与设计规范，色彩、字体、间距、圆角与微颗粒质感 100% 保持一致。

## 核心架构设计

整个 Orbit 收敛为 **四大核心支柱**，各自承载一种完全不同的人类行为与内容形态，互不重叠：

```
1.【流】 ✨ 动态 (Moments)  ── 每天发生的生活（文字、抓拍、心里话、足迹大事件）
2.【图】 📷 相册 (Albums)   ── 高频翻看的主题影集（吃过的蛋糕、美食打卡、旅行）
3.【信】 💌 信箱 (Letters)  ── 慢节奏的深情长信（庄重、仪式感、见字如面）
4.【家】 👤 我们 (Us)       ── 二人的基石与星空（岁月星图、相爱天数、恋爱公约、喜好卡、设置）
```

---

### 1. 详细模块职责与呈现

| 模块 | 涵盖与演进 | 核心心智与场景 | 呈现形式 |
| :--- | :--- | :--- | :--- |
| **✨ 动态 (`moment`)** | 吸收原随想、日记、感谢、留言 | **日常万物与心绪流淌**（高频、零负担）。承载柴米油盐、照片抓拍、当下情绪、委屈道歉、爱意碎念与感恩细节。 | 生活照片流 / 温暖文字卡片混排流 |
| **📷 相册 (`album`)** | 升级原相册 / 图库 | **高频视觉生活画册**（高频翻看）。承载超越时间线的分类主题影集：《吃过的蛋糕 🍰》、《美食打卡 🍱》、《旅行特辑 ✈️》、《臭宝抓拍 📷》。支持新建相册与照片分类。 | 主题影集封面瀑布流 / 专辑内照片网格 |
| **💌 信件 (`letter`)** | 保留原信箱 / 信件 | **庄重思考与深情长文**（低频、慢节奏）。承载周年见字如面、长途思念、深度承诺。 | 拟物信箱、火漆印章、往来回信折叠 |
| **👤 我们 (`us`)** | 整合备忘录、星图天幕、空间档案、账号设置 | **二人的基石与家园**（温存与资料）。承载相爱天数名片、岁月星图天幕、恋爱公约（原《恋爱原则》）、辛芝芝喜好卡（原《关于辛芝芝》）、系统设置与登出。 | 空间主页：星空天幕 + 双人名片 + 公约喜好卡 + 底部设置区 |

### 2. 枝叶属性与筛选机制（动态流内切片）

足迹与感谢**不再作为独立主类型**，而是作为动态上的**可选轻量枝叶属性**：
- **`is_milestone`（📌 足迹）**：记录第 36 次见面、旅行、纪念日等大事件时顺手勾选；
- **`tag: 'appreciation'`（💖 感谢）**：记录感恩对方买礼物、照顾等温情细节时顺手点亮。

在「动态」页面顶部提供克制清爽的筛选胶囊（Filter Pills）：
- **`[ 全部 ]`**：按时间流淌的全部日常、照片与心声；
- **`[ 📌 足迹 ]`**：一键切换为纯粹的大事件时间轴（直观查阅所有见面与旅行记录）；
- **`[ 💖 感谢 ]`**：一键切片为两人专属的情感存钱罐。

## 视觉风格守恒与设计规范约束 (Design Consistency)

本次重构是**信息架构与交互动线的升维**，坚决不引入任何视觉风格的大改动。所有新增组件与重构页面，**必须 100% 严格遵守既有的 `DESIGN.md` 与 Token 系统**：

### 1. 60-30-10 黄金色彩法则守恒
- **60% 画布底色**：沿用月石清白 `--color-bg` (oklch) + 5% 背景 SVG 纸质微颗粒，纯白卡片容器 `--color-surface`，确保阅读安宁通透；
- **30% 墨水排版骨架**：标题与正文严格使用 `--color-text-primary` 与 `--color-text-secondary`，1px 微弱分割线 `--color-border` / `--color-border-light`，中性单色线性图标；
- **10% 焦点高光**：唯一实心行动按钮 (CTA)、状态呼吸圆点使用主题色 `--color-accent`，严禁大面积非克制铺陈。

### 2. 经典三元字体架构守恒 (The Classic Trio)
- **标题 (Serif)**：`Source Serif 4` / `思源宋体`，字重 500，保持出版物文学温度；
- **正文 (Sans)**：`Inter` / 系统苹方 / `思源黑体`，15px 搭配 1.72 黄金行高，保障长篇夜读舒适；
- **时间与数字 (Mono)**：`JetBrains Mono`，12px 天然物理等宽，营造钟表刻度与时间轨道的秩序感。

### 3. 间距、圆角与动效规范守恒
- **间距 Token**：严格使用 `--spacing-xs` (6px)、`--spacing-sm` (10px)、`--spacing-md` (16px)、`--spacing-lg` (24px)；
- **圆角规范**：底栏与卡片统一采用 `--rounded-md` (10px) 与 `--rounded-lg` (14px)；
- **微动效**：按钮与卡片悬浮位移收口在 `(hover: hover)` 媒体查询中，统一使用 `--motion-fast` / `--motion-normal`；
- **严禁任何硬编码**：禁止硬编码 hex/rgb 颜色值或散落尺寸，新增的底栏 TabBar、半屏手势抽屉 BottomSheet、主题相册卡片均 100% 采用既有 Token 与 `OrbitIcons.tsx` 图标族驱动。

## 前端工程治理：外壳解耦架构 (Clean Shell Architecture)

针对“一套代码如何同时支撑 Web 桌面与 PWA 移动端，且绝不打补丁”的诉求，严格遵循业界顶级精品应用（如 Linear、Twitter/X、Slack）的**三层分工规范**：

### 1. 三层架构清晰切分

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 业务逻辑与数据层 (100% 共享，完全无视终端)                    │
│    API、TanStack Query、Contexts、工具函数                      │
├─────────────────────────────────────────────────────────────┤
│ 2. 页面与内容组件层 (100% 纯净复用，零设备判断)                  │
│    动态流卡片、相册专辑卡、信件正文、富文本输入框                  │
│    （只负责渲染数据，内部无任何 isMobile 或复杂媒体查询补丁）       │
├─────────────────────────────────────────────────────────────┤
│ 3. 容器外壳层 (唯一的解耦分水岭！)                             │
│    DesktopShell.tsx (桌面端外壳)  vs  MobileShell.tsx (移动端外壳) │
└─────────────────────────────────────────────────────────────┘
```

### 2. 目录规范与职责边界

```
web/src/components/layout/
├── DesktopShell.tsx     ── 纯桌面：左侧折叠侧边栏、快捷键（⌘K / ⌘J）、桌面微操作
├── MobileShell.tsx      ── 纯移动：顶部原生大标题、底部原生 TabBar、安全区适配
├── ResponsiveLayout.tsx ── 统一路由分发容器（唯一的物理分流点，子组件零感知）
└── BottomSheet.tsx      ── 移动端半屏手势抽屉容器（与桌面 Dialog 多态互补）
```

- **改动安全隔离**：微调手机底栏仅改 `MobileShell.tsx`，零风险影响桌面；微调桌面快捷键仅改 `DesktopShell.tsx`，零风险影响手机；
- **DOM 零冗余**：不采用 `hidden md:flex` 双份渲染隐藏策略，根据环境仅挂载对应平台的原生外壳。

## 端到端人机交互重构（全面去面包屑化）

坚决抛弃 PC 时代的多层级“面包屑导航”（如 `← 返回日记` 或 `首页 / 分类 / 详情`），因为 Orbit 逻辑深度只有两层，面包屑是无价值的视觉噪音。

### 1. PWA 移动端：原生底栏与零门槛输入

#### 导航架构
- **彻底移除移动端左上角的汉堡菜单抽屉 (`☰`)**；
- **引入标准移动端原生底部导航栏 (Bottom Tab Bar)**，适配 `env(safe-area-inset-bottom)`：
  ```
  ┌─────────────────────────────────────────────────────────────┐
  │   [✨ 动态]     [📷 相册]     [ ➕ ]     [💌 信箱]     [👤 我们]  │
  │    (看生活)     (翻影集)     (随时记)    (读长信)     (星图公约) │
  └─────────────────────────────────────────────────────────────┘
  ```
  - **左侧大拇指顺手区**：动态（文字日常）+ 相册（高频翻看主题影集）；
  - **中间高光大按钮**：`[ ➕ ]` 随时随手发；
  - **右侧深情沉淀区**：信箱（慢节奏长文）+ 我们（相爱天数、星图、公约喜好卡、设置）。
- **顶栏极简原生化 (Native Header)**：主页面仅保留纯净大标题（如“动态”），右侧保留搜索 `[🔍]`、通知 `[🔔]` 与 AI 伴侣 `[✨]`；二级详情页左上角仅保留单手可及的原生微返回箭头 `<`。

#### 零门槛即时输入 (Zero-Friction Compose)
- **随时单手呼出**：点击底栏中心高光的 **`[ ➕ ]`** 按钮，底部以弹性动效滑出半屏输入抽屉 (Bottom Sheet)；
- **光标自动聚焦**：无标题栏、不逼选类型，直接拉起系统键盘，打字即发；
- **拇指操作热区**：
  - `[ 🎙️ 语音输入 ]`：按住一键录音，自动转写文字（复用已有语音引擎）；
  - `[ 🖼️ 传图 ]`：一键调用拍照与相册（支持归入特定相册）；
  - `[ 📌 足迹 / 💖 感谢 ]`：可选微开关，需要时一键点亮；
- **发送零跳转**：右上角点“发布”，抽屉即刻收起，新内容无缝置顶在动态流中，全程无路由跳转与白屏。

### 2. Web 桌面端：沉浸式刊物排版

- **常驻左侧边栏**：精简为 `动态` · `相册` · `信箱` · `(底部分区) 我们` · 用户账号卡，激活项始终高亮，承担全局导航上下文；
- **详情页顶栏去面包屑**：
  - 彻底移除 `← 返回某某列表` 等冗长文字；
  - 左上角仅保留极弱化的微返回图标 `[ < ]`（悬浮显现），支持 `Esc` 快捷键与浏览器返回手势；
  - 全画幅留白，彻底聚焦于刊物正文阅读。

## 数据模型与迁移规划

**原则**：遵循 Drizzle Migration 规范，一次性正本清源，严禁业务层胶水代码与运行时 try-catch 兜底。

1. **类型与字段设计**：
   - `entry.type` 枚举收敛为：`moment`（动态）和 `letter`（信件）；
   - `entry` 表增加 `is_milestone: boolean`（足迹大事件标记）；
   - `entry` 表增加 `moment_tag: text`（如 `appreciation` 等轻量情感标签）；
   - 新增/扩充相册表 `album` 及媒体关联，支持主题影集分类（如蛋糕、美食、旅行）；
   - 空间表 `space` 扩展 `rules_content: text`（承接《恋爱原则》公约）；
   - 用户表 `user` 扩展 `preferences_profile: text`（承接《关于辛芝芝》等双方喜好尺码卡）。
2. **存量数据迁移映射**：
   - 现存 `diary`（104 条）、`note`（2 条）、`message`（121 条）统一 UPDATE 为 `moment`；
   - 现存 `timeline`（50 条）统一 UPDATE 为 `moment` 且设置 `is_milestone = true`（平滑保留所有 50 次见面大事记）；
   - 现存 `letter`（50 条）保持 `letter` 原样；
   - 现存 `memo`（3 条）提取《关于辛芝芝》写入用户档案字段，提取《恋爱原则》写入空间公约字段；
   - 现存 `asset`（图片库）自动生成默认相册，支持后续自由归纳分册。
3. **清理与收尾**：
   - 清理所有旧判断分支与组件废弃代码，全栈对齐“动态·相册·信箱·我们”四大核心。
