# AI 聊天多模态与图片上传

> 创建：2026-08-29 · 状态：进行中

## 背景与目标

为 Orbit AI 对话提供一等公民的多模态图文输入与理解能力。用户可在聊天中通过附件按钮、拖拽或剪贴板直接粘贴图片（如照片、生活记录、代码截图、菜单、发票等）向 AI 提问。

核心设计原则：
1. **资产绝对隔离**：图片上传到对象存储独立的 `ai-attachments/` 路径，完全不写入数据库 `asset` 表，杜绝污染日常相册（`/gallery`）。
2. **AI SDK 原生协议**：使用 `ai_message.parts` 保存多模态消息，零 Schema 变更。
3. **上下文经济性**：最近 3 轮保留高清原图，更早历史在送入模型前自动降级为文本占位符，防止 Token 爆炸。

## 交互与界面

1. **输入区域**：
   - 底部工具栏新增中性附件图标按钮，点击唤起系统图片选择；
   - 输入框支持 `onPaste`（截图直接 `Cmd+V`）与 `onDrop`（文件拖拽）；
   - 输入框上方显示微缩卡片预览条，支持显示上传进度与单个移除；
   - 若用户选图但当前模型不支持视觉理解，提示切换到多模态模型（如 Qwen 3.7 Plus / GLM 4.7 Flash）。
2. **消息流气泡**：
   - 用户发送的图片在消息气泡中以圆角网格卡片呈现，点击可全屏放大预览。

## 数据模型

- 无需新增数据库表结构：复用 `ai_message.parts`（JSON 文本列），持久化标准 AI SDK 多模态 Parts 数组。
- 物理存储：保存在 R2 / 本地文件系统的 `ai-attachments/` 独立目录。

## 回归验证

1. 截图粘贴与附件按钮选图上传正常；
2. 提问图片内容，多模态模型（Qwen 3.7 Plus / GLM 4.7 Flash）能精准看图回答；
3. 相册 `/gallery` 保持完全纯净，不包含任何聊天图片；
4. 历史长会话加载与上下文退化正常。
